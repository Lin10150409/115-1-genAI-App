# 公告行動清單整理器

作者：林祐嘉

App 網址：<https://115-1-genai-app-at6voy3y8zmp9x7fhlyaej.streamlit.app/>

## 使用者與問題

常收到課程或社團長公告的學生，容易漏掉該做的事和期限。

這個 App 把一則公告整理成重點、待辦、期限和待確認事項。公告沒寫的資訊不會由模型補上，而是列在「還要再確認」，讓使用者知道還要問什麼。整理完還有不懂的地方，可以直接問「阿發ai助理」。

## 輸入與輸出

**輸入：** 貼上一則公告文字，或上傳一個 .txt 檔（UTF-8 或 Big5 編碼、100 KB 以內），兩者擇一；內容最多 6000 字元。請勿輸入個資、機密或未授權內容。

**輸出：**

| 欄位 | 型別 | 畫面標籤 | 用途 |
|---|---|---|---|
| `summary` | string | 一句話重點 | 說明公告重點，包含原文寫明的時間與地點；內容太少時說明資訊不足 |
| `action_items` | array of string | 我要做什麼 | 列出公告明確要求學生做的事 |
| `deadlines` | array of string | 重要期限 | 列出公告寫明的日期或時間，不自行換算 |
| `missing_info` | array of string | 還要再確認 | 列出公告沒寫、但執行時需要確認的資訊 |

## 延伸功能

| 功能 | 說明 |
|---|---|
| 上傳 txt 檔 | 在「上傳 txt 檔」分頁選檔案，內容會當作公告原文整理。先用 UTF-8 讀取，失敗再用 Big5；都失敗時提示另存為 UTF-8。與貼上文字同時使用時，請使用者擇一 |
| 阿發ai助理 | 頁面最下方的問答區，不必先整理公告就能提問。已整理公告時，問到公告內容只依原文回答，原文沒寫就說「公告沒有提到」。會記得最近 5 輪對話；換新公告、按清除結果或切換 API 開關時清空 |
| 介面 | 頁首橫幅、左側設定欄（API 開關、清除結果、使用方式），結果以四張卡片呈現 |

## 為什麼採用 JSON Schema

四個欄位都是文字或文字清單，JSON Schema starter 已支援，不需要另外定義 Pydantic 模型。程式透過 Responses API 的 `text.format`、`json_schema` 和 `strict=True` 要求結構化輸出，並在保存前檢查欄位與型別。

## 安裝與啟動

需要 Python 3.14。以下指令從 Repo 根目錄開始，在 Windows PowerShell 執行：

```powershell
cd "Midterm Mini-Project"
py -3.14 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-local.txt
python -m pip check
Copy-Item .env.example .env
python -m streamlit run app.py
```

## 設定方式

**本機：** 在 `.env` 填入自己的金鑰。`.env` 已被 `.gitignore` 排除，不會上傳。

```env
OPENAI_API_KEY=
OPENAI_MODEL=gpt-5.4-mini
```

**Streamlit Community Cloud：** 依 `.streamlit/secrets.example.toml` 的格式，把金鑰填入平台的 Secrets。

| 部署設定 | 內容 |
|---|---|
| Repo／分支 | `Lin10150409/115-1-genAI-App`／`main` |
| Main file path | `Midterm Mini-Project/app.py` |
| Python 版本 | 3.14.10（部署 log 顯示的版本） |
| 套件清單 | Repo 根目錄的 `requirements.txt` |

**為什麼資料夾內是 `requirements-local.txt`：** 資料夾名稱 `Midterm Mini-Project` 含有空格。部署時，Cloud 的安裝程式無法正確讀取同層的 `requirements.txt`（錯誤訊息為 `Invalid requirement: 'Mini-Project/requirements.txt'`）。因此資料夾內的檔案改名，讓 Cloud 使用根目錄內容相同的 `requirements.txt`；本機安裝則使用 `requirements-local.txt`。

## 操作範例

1. 打開 App，在左側打開「啟用真實 API」。未打開時只檢查輸入，不會呼叫模型。
2. 貼上一則公告或上傳 .txt 檔，按「整理公告」。
3. 展開「查看本筆結果的原文」，逐欄確認結果。
4. 有不懂的地方，在最下方問阿發ai助理。

以下是虛構公告的雲端測試結果，完整內容見[專題設計與驗收紀錄](第08週_課堂簡化版_專題設計與驗收紀錄.md)。

**原文：**

> 【虛構測試資料】程式設計社期末成果展通知 各位社員好，本學期成果展將於 12 月 18 日（五）下午 2 點在活動中心 301 室舉行。每組請在 12 月 4 日前繳交作品簡介，並於 12 月 11 日前完成海報設計。成果展當天請提早 30 分鐘到場布置。如有問題請聯絡社長。

**結果摘要：**

- **一句話重點：** 程式設計社本學期成果展將於 12 月 18 日（五）下午 2 點在活動中心 301 室舉行，社員需在指定期限前完成作品簡介與海報設計，並於當天提早到場布置。
- **我要做什麼：** 繳交作品簡介、完成海報設計、當天提早 30 分鐘到場布置。
- **重要期限：** 12 月 18 日（五）下午 2 點、12 月 4 日前、12 月 11 日前。
- **還要再確認：** 作品簡介與海報的繳交方式、布置流程、社長聯絡方式。

| 項目 | 狀態 |
|---|---|
| 本機真實 API：正常資料 | 已測 |
| 雲端真實 API：正常資料、資訊不足 | 已測 |

| txt 編碼（UTF-8、Big5）、同時使用、檔案過大；阿發問答流程 | 自動離線測試，以假回應模擬 |
| 阿發回答與公告無關的問題 | 未測 |
| 空白、過長、缺金鑰 | 自動離線測試，未發出請求 |
| 結果保存、再次送出失敗、不合格回應 | 以假回應模擬，不是模型成果 |
| 真人畫面操作空白與過長輸入 | 已測（雲端，API 關閉，0 次請求） |
| 實際服務故障 | 未測 |
| 大量或不同類型的公告 | 未測 |

## 設計修正紀錄

第一次測試時，四個欄位都沒有出現地點「活動中心 301 室」。我在 `summary` 規則加入「原文有寫活動時間或地點時要包含」，再用同一則公告複測，地點就出現了。這只能證明這一筆有改善，不代表所有公告都會如此。

## 成本與限制

- **請求數：** API 預設關閉；打開後每次有效整理或每問阿發一題，各最多 1 次請求，不自動重試。空白或過長的輸入不會發出請求。本專題真實測試共 10 次：本機 1 次、雲端 9 次（基本功能 2 次、延伸功能 3 次、拍攝測試截圖 4 次）。
- **成本：** 呼叫 API 可能產生費用，失敗的請求也可能計費。
- **資料：** 公告內容會傳送到 OpenAI API，請勿輸入個資或機密。
- **範圍：** 一次處理一則公告（貼上文字或 .txt 檔），不支援 PDF 或 Word；結果與阿發的對話紀錄都不會永久保存。
- **正確性：** 格式檢查通過不代表內容正確，結果仍須對照原文。兩筆測試不代表所有公告都能正確處理。
